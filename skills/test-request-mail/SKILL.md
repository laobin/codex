# 提测申请邮件

## 目标

根据需求和代码改动，生成格式固定、影响面清晰、便于测试同事理解和执行的提测申请邮件。

## 工作重点

可以参考 `AI_DOC/features/<功能名>/1-plan.md`、`3-code-review.md`、`5-test-run-lite.md` 和当前 diff 理解提测功能、影响面和验证证据；没有则跳过。

- 先确认所属系统、提测功能和主要影响面；无法判断时说明缺失信息，不强行生成邮件。
- 固定输出格式，不写闲聊和解释。
- 提测功能写需求相关内容，保持清楚、可测试。
- 影响面按前台、后台、其他影响分组；没有内容的分组可以写“无”或省略。
- 内容要覆盖代码改动带来的真实影响，包括登录态、权限、页面、接口、任务、缓存、配置、数据兼容、回调或外部系统。
- 不把未验证内容写成已验证通过；缺少证据时只写“建议重点回归”或“需测试关注”。
- 语言面向测试同事，表达直接、可执行。

## 输出

只输出以下固定格式：

```text
所属系统：<系统名称>

提测功能：
  1、<功能点 1>
  2、<功能点 2>

影响面：
前台：
- <影响点>

后台：
- <影响点>

其他：
- <接口 / 配置 / 定时任务 / 缓存 / 队列 / 数据 / 外部系统影响>

测试重点：
- <建议重点验证项>
```

如果用户明确要求邮件标题，可在正文前增加：

```text
邮件标题：<系统名称>-<功能名>提测申请
```

## 完成后建议

只提示下一步，不自动执行。若缺少验证证据，建议补充测试执行结果；若影响面较大，建议测试优先回归核心链路。
