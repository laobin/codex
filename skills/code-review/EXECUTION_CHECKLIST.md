# code-review 技能执行检查清单

## 何时使用本清单

每当用户触发 code-review 技能（说"代码评审"、"review代码"等）时，按以下清单执行。

---

## 第一步：确认评审目标 ✓

- [ ] 获取项目根目录：`<ROOT> = git rev-parse --show-toplevel 2>/dev/null || pwd`
- [ ] 获取功能名称
- [ ] 获取代码文件列表（支持多个文件）
- [ ] 转换为绝对路径
- [ ] 获取输出路径：`<ROOT>/AI_DOC/features/<功能名>/3-code-review.md`
- [ ] 读取代码文件内容

---

## 第二步：进行评审（关键步骤）

### 2.1 尝试 当前 Codex ⭐

- [ ] **直接调用** `当前 Codex` 工具
- [ ] 传入完整的评审 prompt（包含代码内容 + 6个评审维度）
- [ ] 等待结果

**结果判断**：
- [ ] 成功 → 标记为 ✅ OpenAI Codex
- [ ] 失败 → 进入 2.2 降级流程

### 2.2 降级到主线程（如果需要）

- [ ] 告知用户降级信息："当前 Codex 不可用，降级由主线程评审"
- [ ] **主线程（我）直接评审**：
  - [ ] 读取所有代码文件
  - [ ] 逐维度评审：
    1. [ ] 正确性 - 逻辑、功能、边界、异常
    2. [ ] 安全性 - 漏洞、权限、敏感信息、输入验证
    3. [ ] 性能 - 复杂度、内存、循环、数据库查询
    4. [ ] 可读性 - 命名、结构、注释、复杂度
    5. [ ] 规范性 - 风格、最佳实践、命名、缩进
    6. [ ] 可维护性 - 扩展性、调试性、重复代码
  - [ ] 整理评审结果
- [ ] 标记为 ⚠️ 主线程降级

---

## 第三步：写入评审报告（强制记录模型）

- [ ] 读取现有报告（若存在）
- [ ] 新增轮次记录
- [ ] **填写评审追踪表**：
  ```
  | 第 N 次 | YYYY-MM-DD | 当前 Codex / 主线程 | 当前 Codex / 当前模型 | ✅ 正常 / ⚠️ 已降级 |
  ```
- [ ] **填写评审工具信息**：
  ```
  ### 评审工具信息
  - **工具**：当前 Codex / 主线程 自身分析
  - **模型**：OpenAI Codex / 当前模型
  - **文件清单**：
    - `file1.java` (N 行)
    - `file2.java` (M 行)
  - **降级**：✅ 否 / ⚠️ 是（原因：xxxxx）
  ```
- [ ] 填写评审内容（每个问题标注文件和行号）
- [ ] 保存到输出路径

---

## 第四步：向用户汇报

- [ ] 展示评审工具和模型信息
- [ ] 展示各维度结论表
- [ ] 列出立即修复的问题（P0/P1，附带文件和行号）
- [ ] 列出建议改进的问题（P2/P3）
- [ ] 给出最终判定和处理方式
- [ ] 告知报告文件位置

**如果降级**：
- [ ] 突出标注 ⚠️ 降级状态
- [ ] 说明："本次降级到主线程评审，发现问题可能不如 Codex 评审全面"
- [ ] 提供重新评审选项

**如果有 P0 问题**：
- [ ] 标注"不通过，需修复后重新评审"

**如果有 P1 问题**：
- [ ] 标注"条件通过，需修复后才能合并"

---

## 关键检查点

### ❌ 禁止事项

- [ ] ❌ 不要跳过 当前 Codex 直接用主线程评审（未经用户确认）
- [ ] ❌ 不要隐藏降级信息（必须在报告中标注）
- [ ] ❌ 不要遗漏问题的文件和行号
- [ ] ❌ 不要使用过期的模型名称

### ✅ 必须事项

- [ ] ✅ 必须尝试 当前 Codex
- [ ] ✅ 必须在报告中记录模型信息
- [ ] ✅ 必须标注是否降级
- [ ] ✅ 每个问题必须标注文件和行号
- [ ] ✅ 降级时必须向用户说明
- [ ] ✅ 保留历史评审记录

---

## 常见问题排查

| 问题 | 排查步骤 |
|------|---------|
| 当前 Codex 不可用 | 检查 当前 Codex 工具是否存在 |
| 评审报告未记录模型 | 检查报告开头是否有"评审工具信息"部分 |
| 用户看不出是否降级 | 检查报告和汇报中是否有 ✅ / ⚠️ 标记 |
| 问题未标注位置 | 检查每个问题是否包含[文件:行号]信息 |
| 历史记录被覆盖 | 检查是否使用了 Write（会覆盖）而不是 Edit（追加） |

---

## 评审维度速查

| 维度 | 关键点 | 常见问题 |
|------|--------|---------|
| 正确性 | 逻辑、功能、边界、异常 | 缺少边界检查、异常未捕获 |
| 安全性 | SQL注入、XSS、CSRF、权限、输入 | 未做输入验证、SQL拼接、权限遗漏 |
| 性能 | 复杂度、内存、循环、数据库 | O(n²)、N+1查询、内存泄漏 |
| 可读性 | 命名、结构、注释、复杂度 | 名字不清晰、嵌套过深、缺少注释 |
| 规范性 | 风格、最佳实践、命名、缩进 | 不符合项目规范、命名风格不一致 |
| 可维护性 | 扩展性、调试性、重复代码 | 逻辑耦合、重复代码、硬编码 |

---

## 提示

- 🔵 Codex 在**安全漏洞、性能问题、代码风格**上更强
- 🟡 主线程在**业务逻辑、整体架构**补充上更灵活
- 📊 两者问题发现量：以当前 Codex 直接执行为基准，主线程降级通常会更保守
- 📝 每次评审都记录，便于看到演进和对比
- 🎯 P0/P1 必须修复，P2/P3 作为参考

---

**最后检查**：提交答案前，确认报告中有清晰的模型记录标记 ✅
