# test-design-lite 技能执行检查清单

## 何时使用本清单

每当用户触发 test-design-lite 技能（说"测试设计"、"出测试设计"等）时，按以下清单执行。

---

## 第一步：确认功能目录与文档 ✓

- [ ] 获取项目根目录：`<ROOT> = git rev-parse --show-toplevel 2>/dev/null || pwd`
- [ ] 获取当前分支名：`git branch --show-current`，去掉前缀推断功能名
- [ ] 检查 `<ROOT>/AI_DOC/features/` 下是否有匹配子目录：
  - 匹配到 → 告知用户并使用该目录
  - 未匹配 → 列出所有子目录让用户选择
- [ ] 确认输出路径：`<ROOT>/AI_DOC/features/<功能名>/4-test-design-lite.md`
- [ ] 统计历史轮次数 N（文件已存在则读取轮次数）

---

## 第二步：由当前 Codex 直接测试设计 ⭐

- [ ] 调用 `当前 Codex`，设置 `sandbox: "workspace-write"`，`cwd: <ROOT>`
- [ ] prompt 中包含：
  - [ ] 读取 `1-plan.md`（必读）
  - [ ] 读取 `2-plan-review.md`（必读，提取风险点）
  - [ ] 读取 `3-code-review.md`（可选补充）
  - [ ] 读取 codex 模型配置：`cat ~/.codex/config.toml | grep "^model"`
  - [ ] 设计 3~8 个关键测试场景
  - [ ] 直接写入 `4-test-design-lite.md`（追加模式）
- [ ] 等待 codex 完成

**结果判断**：
- [ ] 成功 → 继续第三步
- [ ] 失败 → 停止，询问用户是否使用主线程降级（降级时主线程设计 + Write 写文件，标注 ⚠️ 降级）

---

## 第三步：向用户汇报 ✓

- [ ] 展示设计工具和精确模型版本（从写入的报告文件头读取）
- [ ] 展示关键测试场景数量与清单（场景名 + 来源）
- [ ] 展示是否允许进入测试执行
- [ ] 告知报告文件位置

---

## 关键检查点

### ❌ 禁止事项

- [ ] ❌ 不要跳过当前 Codex 直接用主线程设计（未经用户确认）
- [ ] ❌ 不要隐藏降级信息（必须在报告中标注）
- [ ] ❌ 不要写"返回 200"或"页面正常"作为验证点
- [ ] ❌ 不要超过 8 个场景（保持最小化）

### ✅ 必须事项

- [ ] ✅ 由当前 Codex 直接执行（sandbox=workspace-write，codex 直接写文件）
- [ ] ✅ 报告中必须记录 codex 模型版本
- [ ] ✅ 必须标注是否降级
- [ ] ✅ 保留历史设计记录（追加写，不覆盖）
- [ ] ✅ 场景必须有具体验证点（接口结果 + 数据结果 + 关键字段）

---

## 常见问题排查

| 问题 | 排查步骤 |
|------|---------|
| 当前 Codex 不可用 | 检查 `当前 Codex` 工具是否存在，询问用户是否降级 |
| 报告未记录模型 | 检查 codex prompt 是否包含读取 config.toml 的指令 |
| 场景过多或过少 | 控制在 3~8 条，核心主流程 > 高风险点 > 关键异常 |
| 历史记录被覆盖 | 确认 codex prompt 中使用追加模式（读取现有内容后追加） |

---

**最后检查**：报告中是否有模型版本记录、场景数量是否合理、是否允许进入测试执行 ✅
