# 初始化项目上下文

## 目标

这个技能用于把当前项目沉淀成 AI 可读、可检索、可复用的项目级上下文。

- 需求来了先看哪里
- 项目怎么启动、怎么验证
- 哪些业务规则长期稳定
- 哪些模块、表、接口或副作用高风险
- 哪些历史问题会影响后续判断

输出不是空模板，而是基于仓库证据整理后的项目事实索引。目标是减少后续 `context-scan`、方案、实现、测试和缺陷修复的重复探索。

## 工作边界

只写项目知识文档：

```text
AI_DOC/global/project-context/
```

不改业务源码、配置文件、构建脚本、数据库脚本和非目标文档。

无法确认项目根目录、用户未授权落盘、需要写入密钥 / 真实密码 / 生产数据 / 敏感客户信息，或目标文档已有大量无法合并的手写内容时，先说明原因，不强行覆盖。

## 工作重点

可以参考已有 `AI_DOC/global/project-context/`、`AI_DOC/global/` 和项目根目录文档理解项目事实；没有则跳过。

### 1. 先建立证据清单

先扫描证据，再写文档。

优先查：

- 项目结构、模块和启动入口。
- README、AGENTS.md、构建配置和脚本。
- 测试命令、测试类和验证记录。
- Controller、Service、Job、MQ、回调、前端页面。
- 表、缓存、ES、向量库和外部系统。
- 已有长期经验、历史坑和高风险规则。

搜索优先使用 `rg` 和 `rg --files`。当证据足够支撑结论时停止，不做全仓库盘点。

### 2. 只写真实项目事实

- 不保留空表。
- 不写“按实际情况填写”“自行启动”“后续补充”这类无效文本。
- 关键事实尽量带代码位置、命令、配置文件或文档来源。
- 缺口写成可追踪待确认项：缺什么、查过哪里、为什么不能确认。
- 不把旧长文档大段复制进入口文档，只做压缩索引并链接来源。

### 3. 保护已有内容

更新前先读取目标文档。

- 空模板可以整体替换为基于证据的版本。
- 已有用户手写事实时，合并新增内容。
- 新证据与旧事实冲突时，标记冲突和来源，不擅自覆盖。

### 4. 项目级文档

项目级文档目录：

```text
AI_DOC/global/project-context/
  00-project-map.md
  01-business-rules.md
  02-dev-runbook.md
  03-test-runbook.md
  04-known-issues.md
```

`00-project-map.md` 回答“需求来了先看哪里”。

文件可以包含：

- 技术栈、启动模块、前端目录、主要业务模块。
- 需求关键词到模块 / 目录 / 入口的路由表。
- Controller、Service、Job、MQ、回调、页面等关键入口。
- 高风险区域、原因和验证要求。
- 数据与副作用地图。
- 长期文档索引。

`01-business-rules.md` 回答“怎么才算业务正确”。

文件可以包含：

- 跨模块或长期稳定的业务不变量。
- 核心业务流程索引。
- 状态、一致性、权限和可见范围规则。
- 需要人工确认的问题。

`02-dev-runbook.md` 回答“项目怎么跑，坏了怎么恢复”。

文件可以包含：

- 标准启动命令、执行目录、成功标志和日志。
- 后端、前端、中间件分项启动方式。
- 不推荐命令和替代方式。
- 依赖组件、端口、本地配置、profile。
- 常见失败和恢复方式。

`03-test-runbook.md` 回答“怎么证明改动没问题”。

文件可以包含：

- 全量、模块、测试类、前端检查、人工验收入口。
- 常用接口验证方式。
- 测试证据要求。
- 通用造数规则。
- 高风险复测策略。
- 验证等级。

`04-known-issues.md` 回答“哪些坑别再踩”。

文件可以包含：

- 高优先级风险。
- 反复踩坑。
- 废弃做法。
- 回归问题。
- 值得沉淀的经验。

## 输出

最后说明：

- 更新了哪些文件。
- 主要内容来自哪些证据。
- 哪些信息已确认。
- 哪些信息仍待确认，以及已查过哪些证据。
- 是否建议继续进入 `function-init` 初始化具体模块文档。

不要声称“项目知识库完整”。只能基于证据说明本次覆盖范围。

## 完成后建议

只提示下一步，不自动执行。

通常建议：

- 项目级文档已足够时，挑一个高价值模块进入 `function-init`。
- 缺测试命令或造数方式时，补项目测试文档；模块测试文档交给 `function-init`。
- 历史坑分散时，整理到 `04-known-issues.md`。
